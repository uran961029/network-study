## 01. 회선 교환 방식 (Circuit Switching)

> [!summary] 통신 전에 전용 회선을 연결해두고 독점해서 통신하는 방식. 유선 전화가 대표적.

### 핵심 개념

- `회선 교환 방식` : 통신 상대와 1:1 전용 회선을 설정하여 통신하는 방식
- 현재 사용처 : 유선 전화 (원리적으로 채택 중, 실제 백본은 점진적으로 패킷 교환으로 전환 중)

### 작동 원리

- 통화 요청 → 교환기가 경로 탐색 → 전용 회선 설정 → 통신 → 종료 후 회선 해제
- 과거에는 교환원(사람)이 플러그를 꽂아 회선을 직접 연결
- 현재는 자동 교환기(기계/컴퓨터)가 처리 → 교환원이라는 직업 사실상 소멸

### 교환기 구조

- 교환기는 트리 구조로 계층화 : 동네 교환대 → 지역 교환대 → 국가 교환대
- 전화번호의 국가번호 / 지역번호 계층 구조는 이 물리적 트리를 그대로 반영
- 같은 교환대 관할 내 → 1단계 처리, 다른 지역 → 릴레이로 단계 추가

> [!tip] 전화번호 계층 구조가 존재하는 이유 = 교환기가 번호를 앞에서부터 읽으며 단계적으로 라우팅하기 위해. 전자 교환기 시대에도 동일하게 적용.

### 특징

|구분|내용|
|---|---|
|연결 방식|1:1 전용 회선 독점|
|연결 절차|통신 전 회선 설정 절차 필요|
|품질|전용 회선이므로 안정적|
|단점|회선 독점으로 낭비 발생 / 교환기 구성 복잡|
|복잡성 이유|N명 연결 시 회선 수 기하급수 증가 + 실시간 점유 관리 필요|

### 현재 상태

- 자동 교환기가 사람 교환원을 대체 (1970~80년대 전환)
- 인터넷 전화(VoIP) 등장으로 회선 교환 방식 점진적 대체 중
- 국제전화가 비싼 이유 : 과거 교환원 인건비 → 현재 해저 광케이블 인프라 비용 + 레거시 요금 체계

> [!tip] 카카오톡 통화, 줌 등 인터넷 기반 통화는 패킷 교환 방식 → 국경 의미 없어짐

## 02. 패킷 교환 방식 (Packet Switching)

> [!summary] 데이터를 패킷 단위로 쪼개서 전송하는 방식. 인터넷과 이더넷의 기반.

### 핵심 개념

- `패킷 교환 방식` : 데이터를 패킷이라는 단위로 분할해서 전송하는 방식
- `패킷` : 전송 데이터의 단위. 헤더(관리 정보) + 페이로드(실제 데이터)로 구성

### 패킷 구조

|구성요소|내용|
|---|---|
|헤더|출발지 주소 / 목적지 주소 / 순서 정보 / 프로토콜 정보|
|페이로드|실제 전송 데이터 본체|

### 패킷 크기

- 패킷 크기는 프로토콜마다 다르게 정해져 있음
- 크기 결정 기준 : 회선 점유 시간 vs 헤더 오버헤드 사이의 균형
    - 너무 크면 → 회선 오래 점유, 오류 시 재전송 부담 큼
    - 너무 작으면 → 헤더 오버헤드 증가, 패킷 수 폭발

|프로토콜|패킷 크기|특징|
|---|---|---|
|이더넷|최대 1500바이트|대용량 데이터 전송 효율 우선|
|ATM|53바이트 고정|실시간성 최우선, 예측 가능한 QoS 보장|

> [!note] 패킷 크기를 정하는 표준화 기구 : 이더넷 → IEEE, IP → IETF, ATM → ITU-T

### 장점

- **연결 설정 불필요** : 회선 교환과 달리 즉시 전송 가능 (단, TCP는 3-way handshake 있음)
- **회선 공유** : 같은 망을 여러 사람이 동시에 나눠 사용 가능
- **1:다, 다:다 통신 가능** : 유튜브(1:다), 줌 화상회의(다:다)
- **프로토콜 혼재 가능** : 같은 망에서 HTTP, DNS, UDP 패킷이 동시에 통신 가능
- **경로 우회 가능** : 라우터가 메쉬 구조로 연결되어 있어 일부 경로 장애 시 자동 우회

> [!tip] 인터넷이 메쉬 구조인 이유 = 원래 미국 군사 네트워크(ARPANET)에서 핵공격 시에도 통신 유지를 위해 설계됨

### 단점

- **순서 보장 없음** : 패킷마다 다른 경로로 이동 가능 → 목적지에서 순서 재조합 필요
- **혼잡 시 지연 발생** : 병목 지점에서 패킷 대기 → 실시간 스트리밍 끊김 현상

### 병목 문제 해결 방법

|방법|설명|
|---|---|
|CDN|전 세계 곳곳에 서버 배치 → 가까운 서버에서 전송|
|회선 증설|해저 광케이블 추가 / 용량 확장|
|QoS|트래픽 우선순위 지정 (실시간 영상 > 파일 다운로드)|
|엣지 컴퓨팅|서버 자체를 사용자 근처에 분산 배치|

### 라우팅 프로토콜

- 라우터끼리 주기적으로 헬스체크 → 장애 발생 시 해당 경로 자동 제거 후 우회
- `OSPF` : 라우터끼리 링크 상태 정보 공유 → 전체 네트워크 지도 생성
- `BGP (Border Gateway Protocol)` : 통신사(AS) 간 경로 정보 교환. 인터넷 규모에서 사용

> [!note] 수렴 시간(Convergence Time) : 라우터 장애를 전체 네트워크가 인지하고 새 경로로 적응하는 데 걸리는 시간. 이 시간 동안 패킷 손실 발생 가능.

> [!tip] BGP는 최단 경로뿐 아니라 통신사 간 정치적·경제적 계약 관계도 반영. BGP 설정 실수 하나가 인터넷 전체에 영향을 줄 수 있음 (2021년 페이스북 6시간 전면 장애 사례)

## 03. 라우터 (Router)

> [!summary] 한줄 요약 LAN과 LAN을 연결하고 IP 주소 기반으로 패킷을 처리하는 3계층 장비.

### 핵심 기능

- IP 주소를 보고 목적지가 내부 LAN인지 외부인지 판단하여 패킷 처리
- LAN과 LAN을 연결하고 목적지에 따라 패킷을 라우팅
- 자신이 관리하는 LAN을 향한 패킷이면 수신, 아니면 인접 라우터로 전송

### 포트 구성

|포트|역할|
|---|---|
|LAN 포트|내부 LAN 연결|
|WAN 포트|외부 인터넷(다른 LAN) 연결|

### 라우터 종류

- `에지 라우터` : 내부 LAN과 인터넷의 경계에 설치하는 라우터
- `인접(이웃) 라우터` : 직접 연결된 다른 라우터
- `Wi-Fi 라우터(공유기)` : 광대역 라우터 + AP가 통합된 장치. 집에서 쓰는 공유기가 이것

### 라우터와 인터넷

- 인터넷 = 라우터로 LAN을 광범위하게 연결한 것
- 라우터들은 메쉬 구조로 연결되어 있음 → 경로 장애 시 우회 가능
- 라우터끼리 연결 매체 : 광섬유 케이블, 통신사 전용선, 해저 광케이블, 위성 등

## 04. 물리 장비

> [!summary] 한줄 요약 AP·허브·스위치·케이블 등 네트워크를 구성하는 물리적 장비들.

### 액세스 포인트 (AP)

- `AP` : 무선 LAN에서 허브/스위치 역할을 하는 **2계층** 장비
- 무선으로 연결된 기기들의 신호를 모아(집선) 유선 네트워크로 연결
- 규격 : IEEE 802.11 (Wi-Fi는 이 표준의 브랜드명)

#### AP 동작 모드

|모드|설명|예시|
|---|---|---|
|인프라 모드|모든 기기가 AP를 경유하여 통신. AP가 교통정리|일반 가정 Wi-Fi 환경|
|애드혹 모드|AP 없이 기기끼리 직접 연결. 중간 관리 없음|노트북-프린터 직접 연결, 에어드랍|

> [!note] 애드혹 모드는 AP가 없으니 보안 관리를 각 기기가 직접 해야 함 → 상대적으로 보안 취약

#### AP vs 라우터 계층

|장비|계층|보는 정보|역할|
|---|---|---|---|
|AP|2계층|MAC 주소|내부에서 어디로 갈지 결정|
|라우터|3계층|IP 주소|내부/외부 판단 및 인터넷 연결|
|Wi-Fi 라우터(공유기)|2+3계층|MAC + IP|AP + 라우터 역할 동시 수행|

---

### 허브 (Hub)

- 원래 기능 : 연결된 모든 포트에 데이터를 그냥 뿌리는 집선 장치. 전원 불필요
- 발전 과정 : 리피터(신호 증폭) 기능 추가 → CPU 탑재로 스위치 기능 추가 → 전원 필요
- 현재 상태 : 시중에서 '허브'라고 파는 제품 대부분 = 실제로는 스위치

> [!note] 캐스케이드 연결 : 포트가 부족할 때 허브끼리 연결하여 포트 수를 늘리는 방식. 스위치끼리도 동일하게 사용.

---

### 스위치 (Switch)

- `스위치` : MAC 주소를 학습하여 목적지 포트로만 데이터를 전달하는 **2계층** 장비
- 허브와의 차이 : 허브는 모든 포트에 뿌림 / 스위치는 목적지 포트에만 전달

#### 스위치 종류

|구분|기반|특징|용도|
|---|---|---|---|
|L2 스위치|MAC 주소|VLAN 가능, VLAN 간 통신 불가|일반 사무실 / 가정|
|L3 스위치|MAC + IP 주소|라우터 기능까지 포함, VLAN 간 통신 가능|기업 코어 네트워크|

---

### 케이블 & 커넥터

- `케이블` : 데이터를 전송하는 물리 회선. UTP(LAN 케이블), 광섬유 등
- `커넥터` : 케이블을 이어주는 연결부

---

### 무선 통신 원리

- 전파 = 전자기파. 빛과 같은 종류로 공기 중(또는 진공)을 이동
- 유선 : 전기 신호를 케이블 안에 가두어 전송 → 손실 적음
- 무선 : 전자기파를 공기 중으로 퍼뜨려 전송 → 거리/장애물에 따라 손실
- 진공에서는 오히려 더 잘 됨 (공기 분자의 방해 없음) → 위성통신이 가능한 이유

> [!note] 엘리베이터 안에서 핸드폰이 안 터지는 이유 = 철제 구조물이 패러데이 케이지 효과를 만들어 전자기파 차단
